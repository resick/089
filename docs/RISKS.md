# 089 — Risks

Scored **L**ikelihood × **I**mpact, each 1–3. Reviewed at each milestone.

## Commercial

| #   | Risk                                                                                       | L   | I   | Mitigation                                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------------ | --- | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | **Low retention**: tourists leave after 3 days; locals don't need a place directory weekly | 3   | 3   | Events as the weekly reason, opt-in "This weekend" digest, seasonal guides, plans/lists. Measure W4 retention for locals from the beta and treat < 15% as a stop-and-rethink signal |
| C2  | **Curation doesn't scale**: featured content goes stale                                    | 3   | 3   | Tiers (only 250–400 featured), 90-day re-verify queue, report button, CMS optimised for a 10-minute curation flow. Budget curator hours explicitly                                  |
| C3  | **Cold-start acquisition**: no budget for paid user acquisition                            | 3   | 2   | SEO web pages, Instagram/TikTok from editorial content, launch timed to a seasonal moment, partnerships with student unions/expat groups (Internations, TUM/LMU)                    |
| C4  | **Slow monetization**                                                                      | 3   | 2   | Keep costs < €150/month to start; affiliate links in Phase 3; sponsored collections (labelled); tourism-board partnership pitch once there's traction                               |
| C5  | Competitors (Google Maps lists, Mit Vergnügen München, muenchen.de, Instagram accounts)    | 2   | 2   | Compete on "now"-ness + trustworthy curation + bilingual + transit-aware. Don't compete on POI breadth                                                                              |
| C6  | Brand "089" can't be registered / conflicts                                                | 2   | 2   | Trademark search before logo work; word-and-figurative mark; parent brand before the 2nd city                                                                                       |

## Technical

| #   | Risk                                                                              | L   | I   | Mitigation                                                                                                                                                                   |
| --- | --------------------------------------------------------------------------------- | --- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | **Wrong "open now"** (stale OSM hours, holidays, exceptions)                      | 3   | 3   | Use `check_date` in quality score; "Hours unknown" if > 12 months old; Bavarian PH handling; tests for DST/midnight; manual spot-check ≥ 95% before launch; report button    |
| T2  | Entity matching/dedup errors across OSM/FSQ (duplicates or wrongly merged places) | 2   | 2   | Conservative auto-match thresholds (name trigram ≥ 0.6 AND ≤ 50 m AND compatible category); everything else goes to a review queue; provenance kept, so merges can be undone |
| T3  | Scope creep / solo-developer burnout                                              | 3   | 3   | Vertical slices with exit criteria; MVP cut list (digest, calendar view and Google sign-in go first); no Phase 2 work before MVP exit                                        |
| T4  | Expo/native-module incompatibility (MapLibre RN on new SDK)                       | 2   | 2   | Pin versions; spike MapLibre in slice 1 with a dev build; fallbacks documented (plain StyleSheet; MapTiler-hosted tiles)                                                     |
| T5  | Map performance on low-end Android                                                | 2   | 2   | Client clustering, simplified style, test on reference device every slice from 7 on                                                                                          |
| T6  | Supabase lock-in / pricing change                                                 | 1   | 2   | Plain Postgres + S3 storage; weekly editorial dump; no proprietary features in the critical path besides Auth                                                                |
| T7  | Ingestion breaks silently (schema change upstream)                                | 2   | 2   | Zod-validated parsing, `ingest_runs` stats with anomaly thresholds (e.g. > 5% deletions aborts the publish), alert to email                                                  |
